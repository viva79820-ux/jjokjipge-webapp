## 3. 전화상담 구조: A안 "예약형 콜백" (10/30 확정)

원칙: 고정비 0원, 로그인 없이 이용 가능, 나중에 060이나 엑스퍼트를 붙일 수 있게 만든다.

**A안. 예약형 콜백 (구현할 구조)**

1. 고객이 상담사 → 상담 상품(예: 사주 30분) → 희망 날짜·시간을 고른다.
2. 연락처를 입력한다. 회원은 자동으로 입력되고, 비회원은 이름·휴대폰 번호(연락용, 인증 없음)·이메일(인증 코드)을 입력한다.
3. 결제 방법을 고른다.
   - 무통장입금: 수수료 0원. 계좌를 안내하고, 관리자가 입금을 확인하면 예약이 확정된다.
   - 카드결제(PG): 건당 수수료만 나간다. 결제되면 바로 확정된다.
4. 예약이 확정되면 이메일로 알린다(무료).
5. 예약 시간에 상담사가 **매장 전화로 고객에게 건다.**
6. 상담이 끝나면 관리자가 "상담 완료"로 처리한다. 고객 마이페이지(또는 예약조회)에 기록되고, 후기를 쓸 수 있게 된다.

- 고정비: **0원**. 변동비: 카드결제 시 PG 수수료만.
- PG 심사와의 관계 [확인]: 포트원 안내에 따르면 사주·운세·타로는 입점 제한이 없지만 "포인트 충전" 방식은 제한을 받는다. A안은 **날짜를 지정한 상담 상품을 직접 판매**하는 구조라서 충전 방식보다 심사에 유리하다. 다만 승인이 보장되는 것은 아니다.
- 단점과 대응
  - 상담 시간 초과나 추가 요금은 사람이 처리해야 함 → 상담 단위를 시간제 상품으로 판매
  - 노쇼·환불 → 환불 규정이 필요함(고객 자료). PG 심사 때도 취소·환불 조건이 명시돼 있어야 함
  - 상담사 개인 번호가 노출될 수 있음 → **매장 전화로만 발신**하는 운영 규칙을 둠. 외부 파트너 상담사가 생기면 050 안심번호 검토(번호당 월 1,100원 수준 [미확인])

**함께 설계해 둘 확장안**

- B안. 상담권 + 매장 대표번호: 상담권을 결제하고 예약번호를 가지고 매장 대표번호로 직접 전화. 고정비 0원. 필요할 때 추가
- C안. 네이버 엑스퍼트 연결: 제휴가 승인되면 전화상담 버튼을 엑스퍼트 상담사 페이지로 연결. 결제·통화·정산을 네이버가 처리(수수료율 [미확인]). 상담사 테이블에 링크 필드만 미리 둠
- D안. 060: 초기 약 110만 원 이상 [확인: KT 자료 10/29]. **보류**

[결정 필요] 전화상담 상품의 가격과 시간 단위(매장 가격을 그대로 쓸지, 전화용 가격을 따로 정할지), 상담 가능 시간대, 환불 규정

## 4. 회원·인증

- Supabase Auth의 **이메일 인증**(인증 링크나 6자리 코드)을 쓴다. 추가 비용은 없다.
- Supabase Authentication → URL Configuration에 Site URL(Vercel 주소)과 Redirect URLs(localhost, Vercel 주소)를 설정해야 인증 링크가 제대로 돌아온다.
- 1차 시안: Supabase 기본 메일 발송으로 테스트한다.
- 오픈: 외부 메일 발송 서비스를 연결한다. Supabase 요금표에 "custom SMTP 포함"이라고 되어 있다 [확인].
  - 1순위 **Resend 무료**: 월 3,000통, 하루 100통 [미확인, ChatGPT 조사]. 회원가입 인증 메일 규모에는 충분하다.
  - 대안 Brevo 무료: 하루 300통 [미확인]
  - 발송 도메인의 DNS에 SPF·DKIM·DMARC를 설정해야 한다. 그래서 **angelsaju.com 권한을 확보한 뒤** 연결한다.
  - 네이버·다음 메일의 도달률은 공식 자료가 없다. 실제 네이버·다음·카카오·지메일 계정으로 받아 보는 테스트를 한다.
- 마이페이지: 예약·상담 내역, 주문·배송 내역, 내 후기, 1:1 문의 내역, 회원정보 수정, 탈퇴
- 비회원: 예약번호(또는 주문번호)와 이메일로 조회
- 참고: 이메일 인증은 본인 확인 효과가 약하다. 대신 카드결제 단계에서 카드사 본인 인증이 이루어진다.

## 6. 후기와 네이버 연동

- [확인, ChatGPT 조사·네이버 개발자 문서 기준] 네이버 플레이스 리뷰를 조회하는 **공개 API나 공식 위젯은 없다.** 네이버 지역 검색 API는 사업장 정보만 주고 리뷰는 주지 않는다. 크롤링은 허용 근거가 없어서 쓰지 않는다.
- 구현 방식
  1. **자체 후기**: 상담 완료나 구매 완료 건에만 작성할 수 있게 해서 신뢰도를 확보
  2. "**네이버 리뷰 보러가기**" 버튼으로 플레이스 리뷰 페이지에 연결
  3. (선택) 고객 동의를 받은 후기만 관리자가 직접 등록. 네이버 리뷰를 그대로 옮기는 것은 허용 여부가 불확실하므로 하지 않음

## 11. 개발 방식

- 저장소: GitHub `jjokjipge-webapp`(회사 계정, 비공개). 로컬 경로 `C:\Users\angel\Desktop\jjokjipge\jjokjipge-webapp`
- 스택: Next.js 16(App Router, `src/` 없이 `app/`이 루트) + TypeScript + Tailwind CSS v4 + Supabase(Auth·DB·Storage) + Vercel
- 지역
  - Supabase: **서울(Northeast Asia, ap-northeast-2)**. 첫 프로젝트가 시드니로 만들어져서 서울로 다시 만들었다. 지역은 만든 뒤에 바꿀 수 없고, 데이터가 없을 때 바꾸는 비용이 가장 적기 때문이다. 일반 지역(Asia-Pacific)을 고르면 Supabase가 여유 용량에 따라 위치를 정하기 때문에 서울이 보장되지 않는다 [확인: Supabase 지역 문서]
  - Vercel 함수: **서울(icn1)**. `vercel.json`의 `regions`로 설정한다. 기본값은 미국 워싱턴(iad1)이라 DB와 멀다 [확인: Vercel 문서]
- 화면 범위(11/2 변경): **휴대폰·태블릿 반응형.** 화면 폭에 맞춰 꽉 차게 늘어나고 최대 폭은 1024px. 그보다 넓은 화면(PC, 태블릿 가로)에서는 1024px로 가운데 정렬. PC 전용 레이아웃은 만들지 않음. 세부 규칙은 AGENTS.md 3장
- 도구 역할
  - 코딩과 커밋: 회사 계정의 **ChatGPT Codex CLI**(GPT-6.1 Sol). 데스크톱 앱 없이 CLI만 쓴다. **커밋 제목·설명은 한글로 쓴다**
  - 기획 세션: 11/4부터 **Codex 웹**(GitHub 연동, 이 저장소를 읽음). 지침은 `docs/planning/README.md`. 10/30~11/3은 Claude 프로젝트에서 진행했다
  - 기획 세션(계획, 구조 판단, 핵심 코드 검토(결제·인증·DB 권한), 문서화, Codex CLI 프롬프트 작성): 10/30~11/3 Claude 프로젝트 → 11/4부터 Codex 웹
  - ChatGPT: 웹 조사(심층 리서치), 디자인 분위기 시안 이미지. 핵심 수치는 Claude가 공식 사이트로 확인
- 지침 파일: 저장소 맨 위의 **AGENTS.md**. 맨 위의 Next.js 블록은 `next dev`가 관리하므로 건드리지 않고, 그 아래에 프로젝트 규칙을 둔다
- 브랜치 (PR 없음)
  - `main`은 배포용이다. 올라가면 Vercel 실서비스와 Supabase DB에 자동으로 반영된다(Supabase GitHub 연동의 Deploy to production)
  - 작업마다 영어 이름의 브랜치를 만든다(예: `feat/counselor-list`) → 커밋하고 push → Vercel 미리보기 확인 → **작업자 승인 후 로컬에서 main에 merge하고 push** → 브랜치 삭제
  - 미리보기도 실서비스와 같은 DB를 쓴다. 그래서 DB 구조 변경은 마이그레이션만 담은 브랜치로 먼저 main에 합친 다음 화면 작업을 한다
- 보안 원칙: API 키와 비밀번호는 `.env.local`에만 두고 GitHub에 올리지 않는다. **모든 테이블에 RLS를 켜고 정책을 같이 작성한다**(테이블 자동 공개 설정이라 필수)

DB 테이블 초안: profiles(회원), stores(매장), counselors(상담사, 소속·승인 상태·엑스퍼트 링크), consult_products(상담 상품), reservations(예약, 비회원 정보 포함), products / orders / order_items(타로샵), classes(강의), reviews(후기), notices / faqs / inquiries(고객센터), contents(블로그·인스타·유튜브 링크)
